# data_table_2 をリポジトリに取り込んで改変する

ユーザー一覧のテーブル表示に使う **`data_table_2` を pub.dev から取得するのをやめ、`frontend/packages/data_table_2/` に取り込んだうえで 1 行だけ改変して使う**。改変内容は、本体側のテーブルを中央寄せしている `Column` を左寄せに変えることである。ADR 0006 で採用を決めたパッケージそのものは変えておらず、その取得元と改変の扱いだけを決める。

## 改変が必要な理由

このテーブルは**左端の「ユーザー名」列を固定**する設定で使っている。パッケージはこのとき表示領域を「固定列」と「それ以外の本体」の 2 つに分け、それぞれ別のテーブルとして描いて横スクロールを同期させる。

問題は本体側の組み立て方にある。`lib/src/data_table_2.dart` で、本体側は `crossAxisAlignment` を指定していない `Column` に入れられており、**この既定値は中央寄せ**である。そのため、与えられた幅よりテーブルの中身が狭いと本体側だけが中央へ寄る。一方で固定列は左端に残るため、**そのあいだに空白が開く**。

これは次の状況で実際に起きる。

- 利用者が列の幅を手で縮めたとき（縮めた量の半分がそのまま空白になる）
- 画面がテーブルの必要幅より広く、余白が生じたとき

固定した列とその右の列が離れて表示されるため、1 つの表に見えなくなる。**この `Column` はパッケージの内部にあり、コンストラクタの引数でも継承でも外から差し替えられない。**

## 検討した選択肢

**画面側で、テーブルに必要以上の幅を渡さないようにする** — 最初に採った方法で、テーブルを包む箱の幅を必要幅までに抑えれば余白が生まれず、中央寄せも起きない。追加の依存も改変も不要である。採らなかったのは、**利用者が列を縮めたときには効かない**ためである。列を縮めるとテーブルの中身だけが狭くなり、箱の幅は変わらないため、やはり中央へ寄って空白が開く。箱の幅をテーブルの実幅に追従させる手段はなく（パッケージが実幅を外へ公開していない）、根本の解決にならない。

**列を縮められないようにする** — 空白が開く操作そのものを塞ぐ案。画面の仕様として「列幅は広げられるが縮められない」と決めれば、改変は不要になる。採らなかったのは、**表示しきれない文字を読むために幅を調整するという操作の自由度を、実装の都合で削ることになる**ためである。

**フォークして `git:` 依存で参照する** — リポジトリに他人のコードが入らず、改変はフォーク側の履歴に残る。採らなかったのは、**フォークを置いた GitHub アカウントへの依存が生まれる**ためである。本リポジトリは clone して使われるテンプレートであり、利用者側もそのフォークを参照し続けることになる。アカウントやリポジトリが失われればビルドできなくなる。

**パッチファイルを置き、ビルド前にキャッシュへ当てる** — リポジトリに入るのは数行のパッチだけで済む。採らなかったのは、**`pub get` のたびにキャッシュが元へ戻る**ためである。パッチを当てる手順を増やすことになり、実行を忘れた環境や CI では直らないまま動く。「clone して `pub get` すれば誰の環境でも同じ結果になる」という性質を失う。

**改変せずに使い、空白を許容する** — 何もしない案。採らなかったのは、固定列とその右の列が離れて見える状態が、表として成立していないためである。

## 結果として生じること

- **取り込んだ 3,705 行は、本リポジトリのコードとして保守する対象になる。** `pub get` では更新されない
- **upstream の更新とバグ修正は自動では入らない。** 必要になった時点で、新しい版のファイルで置き換え、同じ 1 行を当て直す
- **Flutter SDK の更新でビルドが通らなくなった場合、自分たちで直すことになる。** パッケージの保守が個人 1 名に依存している点（ADR 0006）と合わせ、この負担は最初から織り込んでおく
- **改変箇所は 1 行に限定する。** 置き換え作業を機械的に済ませられる状態を保つため、他の変更は加えない。該当行にはその旨のコメントを残してある
- **取り込むのは `lib/` と `LICENSE`、`CHANGELOG.md` だけとする。** `example` / `screenshots` / `test` は含めない（2.3MB のうち 164KB に収まる）。`pubspec.yaml` からも、含めなかったものへの参照（`screenshots`）と、path 依存では解決されない `dev_dependencies` を削除している
- **BSD-3-Clause により、改変して取り込むこと自体に制約はない。** `LICENSE` を同梱し続ける義務だけが残る
- **`pubspec.lock` には相対パスで記録される。** 環境ごとの差は生じない
